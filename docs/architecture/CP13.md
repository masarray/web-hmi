# CP-13 — Multiple PLCs, one HMI connection

Start from merged CP-12 \`a25278422a327e25a012623b66f7fc309af95d26\`.

Based on FUXA's useful device-list and common runtime workflow
(\`server/runtime/devices/modbus/index.js\`, MIT), independently implemented
with Angular signals and Node.js TypeScript.

## From a user's point of view

Open **Devices & Tags → Multiple PLCs**, choose **Add PLC**, enter the device
address and register tags. Choose another device to edit its mapping. One
server access key loads the running list and enables **Apply all PLCs**.
The status of each PLC appears beside its name. A new connection is
tested with a read cycle before replacing the existing data stream.

Graphical objects can bind \`PLC1/Motor/Run\`, \`PLC2/Motor/Run\`, etc.;
different devices may share the same raw Modbus register name.
The old **Single PLC** workflow remains for existing projects.

## Engine design

- One reusable Node Modbus TCP poller per configured PLC, not per viewer.
- All viewers subscribe to qualified tags over the same \`/ws/tags\`.
- Maximum 16 devices x 128 tags. IDs are validated and stable.
- A device add/update is probed before activation. Failure does not stop
  existing acquisition. A device rename changes metadata only and does
  **not** reconnect the Modbus transport.
- During successful updates only changed PLCs reconnect. Removed/
  superseded tags receive explicit BAD/null. Per qualified tag monotonic
  sequence numbers survive device replacements; the rest of the HMI
  remains GOOD.
- Saved device list is committed atomically to
  \`config/modbus-fleet.json\` and restored on restart. No PLC passwords
  or administrator tokens are serialized.
- The existing single-PLC entrypoints and JSON editor data remain intact.
  When the fleet is activated, the old single-source apply endpoint is
  blocked to prevent two controllers managing the same project.
- Authenticated, Origin-limited management API:
  \`GET /api/fleet\`, \`POST /api/fleet/apply\`,
  \`POST /api/fleet/test\`, behind \`HMI_ADMIN_TOKEN\`.
  No Modbus write operation is available.

This is a production-oriented multi-device runtime intended for internal
acceptance testing. CI covers software regression, not vendor hardware
certification. Deploy operator access through an authenticated HTTPS
gateway, and test reconnect timing/plant communications on the real network.
