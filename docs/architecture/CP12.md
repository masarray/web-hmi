# CP-12 — PLC connection check & live device health

Baseline: CP-11 merged main `6088da1beb84274f4e101e441cb56d52b4d3c45f`.

Reference reviewed: FUXA `server/runtime/devices/modbus/index.js` at
`a7705f084c1439edf1b27c1f69c737b8d6de0e00`. Its useful idea is
to emit device connection status, clear values on disconnect, and reuse
one transport for polling. We implement the same operator workflow
with a small typed Node adapter and Angular-native editor.

## Operator workflow

In **Devices & Tags**, enter the Modbus PLC host, registers and server
access key. Click **Test PLC** to perform a full, read-only FC01–FC04
read cycle against the candidate device. The active device is **not**
replaced; no config is persisted; no write command is available.
Success shows latency and optimized request count; failure shows a
specific message and preserves the live source.

**Check server** displays **Online / Connecting / Connection problem /
Offline / Not configured** and a compact group of runtime metrics:
successful polling cycles, register reads, last valid read time and
cycle duration. Only successful, authenticated status queries enable
one shared refresh interval (4 seconds) while the mapping editor is
open. The refresh interval stops when the editor closes, token changes,
or the component is destroyed. There is no per-symbol polling timer.

## Implementation

- `server/adapters/modbus-tcp.ts`: no new dependencies; lightweight
  read-only counters and timestamps, bounded last error string. Values
  update at the actual read, successful cycle and error transitions.
- `server/device-runtime.ts`: `testConnection(config)` uses the existing
  adapter factory and health probe, without touching current source,
  revision or persistent config. An already-running apply excludes a test.
- `server/device-config-api.ts`: new authenticated, origin-checked
  `POST /api/device/test` with the existing 48-KiB JSON cap.
  Response: `{ok:true,latencyMs,readRequests,host,unitId}`.
  All management API routes remain disabled without `HMI_ADMIN_TOKEN`.
- Angular status and per-device counters are read-only diagnostics;
  they do not claim a working connection until a real polling cycle
  reports `HEALTHY`.

## Acceptance

Node tests cover unaffected old device during successful/failed
candidate tests, no persistence, auth and Origin rejection, successful
read counters, fault/recovery counters. Playwright covers novice test
action, live counters, failed probe and retention of mapping. Existing
CP-01–CP-11 suite, Node/Angular typecheck and production build remain
mandatory. All changes are a new PR with CI and post-merge CI.

Operational scope: explicitly configured industrial device IPs,
read-only Modbus TCP and live source monitoring. Before deployment
across operator workstations, use a secure authenticated HTTPS gateway;
CI does not replace validation on actual site PLCs.
