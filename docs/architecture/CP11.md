# CP-11 — Authenticated live Modbus configuration from Web HMI Studio

**Baseline:** merged, CI-verified CP-10 main
\`a603ca07163d6ed803ab7b2bff05f64d8e84e95b\`.

## Operator workflow

The existing **Devices & Tags** editor now has a server connection section.
Enter an administrator token, click **Check server**, review the revision and
status, then **Apply to server**. The mapping does not need to be moved to
the Node host or loaded with a restart for each change.

A candidate mapping is first validated using the same shared TypeScript
schema as the browser and Modbus backend. A short-lived read-only Modbus
adapter performs a full successful polling cycle **before** replacing the
active source. If the probe fails, existing acquisition continues. If
validation or configuration persistence fails, existing acquisition is not
stopped. After a successful probe and durable save, old polling is stopped,
the tag cache and browser quality states are reset, and the next adapter
starts with a clean sequence counter. No Modbus write function is added.

## Setup

Set \`HMI_ADMIN_TOKEN\` to a **random token of at least 32 characters** in
the Node server environment, then start \`npm run start:server\`. Without
this environment variable, the configuration API endpoints do not exist;
the original DEMO or manually configured read-only source continues.

The control API is distinct from the existing telemetry WebSocket:
- \`GET /api/device/status\`: authenticated revision, active config and health
- \`POST /api/device/apply\`: authenticated JSON \`{revision,config}\`,
  preflight-probed and applied sequentially, read-only

Both routes require a bearer token and allowlisted \`Origin\`. The API uses
a 48-KiB request cap and no-cache responses. Token digests are compared
in constant time. No token is written to localStorage, project JSON,
export files or logs. Revisions prevent one stale engineering browser from
silently overwriting another user's newer configuration.

Applied settings are durably saved using a temporary restricted-permission
file and atomic rename to \`config/modbus-active.json\`. At the next server
startup, the active configuration is restored when admin mode is enabled,
unless an explicit \`HMI_SOURCE\` and corresponding config overrides it.

For remote engineering workstations, serve Angular and the API through the
**same authenticated HTTPS reverse proxy** (route /api/device and /ws/tags
to the Node server). The Node listener remains loopback-bound by default,
and direct Internet access to its unauthenticated telemetry socket must
not be enabled.

## Fault semantics / limitations

- Source quality is never inherited across configuration replacement.
- No automatic restart of a previously healthy device on a rejected probe.
- Live operator edits are explicit; mapping field changes do not connect to
  PLCs until **Apply to server** is pressed and authorization succeeds.
- This does not add Modbus writes or a remote control API.
- Administrator token authentication is a first cut. For production networks,
  add role-based identities, transport-level TLS termination, request audit,
  secret rotation and plant-specific access policy. Existing status quality,
  SVG editor/animation and read-only Modbus registers remain intact.
- Fault tests cover rejected credentials/origins, invalid mappings, stale
  revisions, persistence failures, failed candidate health and post-apply
  tag-source reset. Chromium tests cover the engineering GUI flow.
- No artifact handoff requested; validate CI on PR and \`main\`.
