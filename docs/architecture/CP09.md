# CP-09 — Typed read-only Modbus mappings and safer engineering workflow

**Starting baseline:** merged CP-08 main \`7518923a23466f6e838e499c5f75aab0320bf263\`.
FUXA studied at pinned \`a7705f084c1439edf1b27c1f69c737b8d6de0e00\`:
- \`server/runtime/devices/modbus/datatypes.js\`: typed register decoding, signed values, word swap.
- \`server/runtime/devices/modbus/index.js\`: grouping, connection reuse, timeout and source status.

This implementation remains independent TypeScript/Node. No legacy FUXA
runtime, write commands, remote PLC access, or extra decoding dependency.

## Supported read mappings

| Function | Modbus memory | Data types | Frame limit |
| --- | --- | --- | --- |
| FC01 | Coils | bool | 128 bits/request |
| FC02 | Discrete inputs | bool | 128 bits/request |
| FC03 | Holding registers | uint16, int16, uint32, int32, float32 | 32 registers/request |
| FC04 | Input registers | uint16, int16, uint32, int32, float32 | 32 registers/request |

Addresses are **zero-based PDU addresses**. This is deliberately different
from vendor "40001" human-readable register notation. All Modbus operations
are read-only. 32-bit values use two contiguous registers and configurable
\`wordOrder\`:
- \`ABCD\` (default): most significant word first, each word big-endian.
- \`CDAB\`: two 16-bit words swapped; bytes inside each word unchanged.

No custom byte rotation, S64, Float64, String or scaling expression is
included in CP-09. Each decoded value is boolean or finite JavaScript
number; NaN/Infinity rejects the read cycle and degrades tags to BAD/null.
Existing CP-08 mappings with no dataType still decode FC03/FC04 as uint16.

## First-run mapping without huge installs or inline JSON

A ready-to-edit template: \`config/modbus-lab.example.json\`.

1. Copy it to \`config/my-lab.json\` and edit the tag IDs, function codes,
   zero-based addresses, types and word order.
2. Run \`npm run check:modbus -- my-lab.json\` to validate and show the
   grouped network request plan **without contacting any Modbus endpoint**.
3. To enable the loopback Modbus laboratory source, set
   \`HMI_SOURCE=modbus-lab\` and
   \`HMI_MODBUS_CONFIG_FILE=my-lab.json\`, then \`npm run start:server\`.
4. Angular Studio's Preview still offers a separate Local Simulator and
   Node tag source. It labels the server MODBUS LAB, not field-grade SCADA.

Only a JSON basename inside \`./config/\` is accepted. Both file mapping and
old \`HMI_MODBUS_TAGS\` inline options remain supported; configuring both
simultaneously is rejected. The unchanged default server is CP-07 DEMO.

## Acceptance and failure behavior

- Pure unit tests cover bit packing, signed conversion, 32-bit word swaps,
  overlapping mappings, crossing the 32-register/128-bit limits, overflow,
  unknown type/config attributes, NaN/Infinity and snapshot preservation.
- Loopback fake TCP server tests fragmented MBAP frames and **all four
  function codes**, typed values, BAD on invalid floats/exceptions and GOOD
  recovery. Existing CP-01–CP-08 suite must still pass.
- Source transport remains one poll loop shared across browser viewers, with
  bounded timeout/reconnect, monotonic sequence and explicit BAD/STALE.
- CI also validates the sample mapping with zero network access.

## Non-goals and security

This is a **local laboratory read-only** integration. Remote device IP
addresses remain explicitly rejected. Do not represent this as certified
industrial SCADA: authentication, secure remote bridging, audit storage,
vendor register convention import, real hardware qualification, controls,
historian, or full FUXA graphical parity remain outstanding.
