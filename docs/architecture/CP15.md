# CP-15 — Trends & Historian for multi-PLC Web HMI

**Base:** current verified main \`601045cdecf553115dfe27e4f9745378bb229208\`, including
all CP01–CP14 milestones **and parallel dynamic SVG symbols**. No old editor baseline is copied.

Inspired by FUXA's \`docs/HowTo-Chart-Control.md\` and the
\`client/src/app/gauges/controls/html-chart/\` trend selection/workflow
(MIT upstream a7705f0), but this engine and Angular view are original.

## Operator use

Open **Trends**, enter the existing HMI server key and connect. Expand
**Recording settings** once, choose up to eight tags, and save. Data is
logged centrally in Node regardless of how many screens are open.
Choose **15 minutes · Live**, 1 hour, 6 hours or 24 hours and **Refresh chart**.
The 15-minute view refreshes once every ten seconds while visible.
The operator does not have to edit JSON, start a separate simulator,
install a database or create a separate socket per PLC.

Live Chart is a **10-second refreshed historical view**, not an
oscilloscope or guaranteed sub-second capture. Every 1–60 seconds
(configurable) at most one sample per tag is logged; quality state changes
are retained immediately and render a visible gap. Faster PLC transients
cannot be guaranteed captured at that configured sampling rate.

## Efficient server design

- The existing Tag Hub feeds the historian only **after** accepting a
  fresh, strictly increasing sample sequence. Same 1–16 PLC pollers,
  shared WebSocket fan-out and one alarm engine.
- Selection is explicit: at most eight recording tags (e.g.,
  \`PLC1/Motor/Current\`), not 2,048 unbounded tags written to disk.
- One buffered flush per second (or 256 records), no per-sample
  fsync/transaction. A crash may lose up to one flush interval.
- UTC-day-partitioned \`config/historian/trend-YYYYMMDD.jsonl\`.
  Retention 1–7 days, checked when a new UTC day is recorded.
  A per-day hard file limit (128 MiB) blocks unchecked disk growth;
  storage errors are surfaced and do not stop Modbus acquisition.
- Typed, revision-checked recording rules written atomically at
  \`config/historian-config.json\`.
- Query accepts at most 24 hours and <=480 output points per tag.
  It **streams** stored files instead of loading day-long arrays.
  Time-bucket compression preserves min/max spikes and BAD/STALE
  gaps, so long histories do not create huge browser SVGs.
- SVG plots are drawn with Angular template bindings, no third-party
  chart engine, dynamic HTML or user-executable expressions.
- Source replacement inserts a quality gap and does not mix the
  previous PLC's values into a new acquisition session.

## Access and failure handling

API under the already-authenticated, Origin-checked Node control plane:
\`GET /api/trends\`, \`POST /api/trends/config\`,
\`POST /api/trends/query\`. No PLC write operations, browser-supplied
file paths or arbitrary SQL. UI credential stays in memory.

Unknown/out-of-window queries, duplicated tag IDs, unsafe tag names,
oversized requests, and unauthorized Origins are rejected. History is
not exposed to untrusted network browsers: deploy behind an
authenticated HTTPS reverse proxy for operator workstations.

CI regression verifies shared validation, sample throttling, persistent
restart/replay, extreme-value decimation, fail-closed storage behavior,
HTTP authorization, Angular production build and Playwright workflow.
Real device test/retention sizing remains part of site commissioning.
