# CP-08 — Local Modbus TCP read-only laboratory adapter

Built from the **merged, CI-green CP-07 main**:
\`fd7d62c733421e161c347a3e6f19d8b3640b2662\`.

FUXA reference: \`server/runtime/devices/modbus/index.js\` at commit
\`a7705f084c1439edf1b27c1f69c737b8d6de0e00\`. Its useful patterns
are reuse of a single transport, serialized polls, timeout/status reporting
and server fan-out. Our implementation is standalone typed Node.js code.

The adapter deliberately supports **only loopback endpoints**, Modbus
**FC03 holding registers** and **FC04 input registers**, unsigned 16-bit
values, and a finite 128-tag mapping. Adjacent registers are coalesced into
one 32-register maximum read per function code. One transport and one
poll loop serve all WebSocket/browser subscribers. No FC05/06/15/16 writes
or control endpoints exist, and no remote IP addresses are supported.

Failure semantics: protocol exception, malformed frame, timeout or transport
loss disconnects the source, reports DEGRADED, and publishes BAD/null for
all mapped tags. Source reconnects with bounded backoff; recovery publishes
fresh GOOD with monotonic sequence. Browser-side 3 s STALE still applies
independently to source and heartbeat availability. Unknown tags remain STALE.

Default \`npm run start:server\` still starts the CP-07 demo source.
To opt into *laboratory* Modbus:

\`\`\`sh
HMI_SOURCE=modbus-lab HMI_MODBUS_PORT=15020 \
HMI_MODBUS_TAGS='[{"tagId":"Plant/Motor","functionCode":3,"address":0},{"tagId":"Pump/Pressure","functionCode":4,"address":5}]' \
npm run start:server
\`\`\`

Optional: \`HMI_MODBUS_HOST=127.0.0.1\`, \`HMI_MODBUS_UNIT=1\`,
\`HMI_MODBUS_POLL_MS=1000\`, \`HMI_MODBUS_TIMEOUT_MS=800\`.
To test, use a separate loopback fake Modbus server (Node integration
tests run their own). In Studio Preview choose Node.js tag server and
bind a symbol to a tag in the mapping. UI identifies source as
**LAB/DEMO, read-only**, never a production industrial connector.

Limitations: unsigned 16-bit only; no S32, FLOAT32, FC01/FC02, register
byte order, project configuration UI, field-IP access, TLS/authentication,
historian, writes, alarm acknowledgment, or production qualification.
The server still binds 127.0.0.1 and uses an Origin allowlist, not full
authentication. Do not deploy on uncontrolled networks. Browser-side
metrics, real device commissioning and source provenance remain future work.
